JCink Installation Guide

How to install Atlas on your JCink forum

This guide walks you through installing Atlas on your JCink forum. You'll need access to your forum's Administration Control Panel (ACP) and the ability to edit the Member List templates.

Tip: If you're not comfortable editing templates, ask your forum administrator for help — the changes are simple but need to be placed in the correct templates.

Important: Understanding data-field and Controls

Read this before you start editing templates. It will save you time and prevent common mistakes.

Design Freedom: You can style your member cards and controls however you want. Use any HTML structure, classes, or inline styles. The only requirement is that the data- attributes are on the correct elements.

The data-field attribute is just a label for the type of data. Atlas uses these labels to build filters and sort options. You can name your fields anything — the examples use roleplay character fields like "species" and "faceclaim." You might use "location," "interests," or any other custom data.

data-field — The Value Must Be Contained

data-field must be placed on the element that contains the actual value. Labels, wrappers, and other display elements should not have data-field.

✅ Correct: data-field on the value element

<div>
    <strong>Species:</strong>
    <span data-field="species" data-sortable="true">Human</span>
</div>

Why this works: Atlas reads the value "Human" from the span. The label "Species:" is ignored — it's just for display.

❌ Incorrect: data-field on a wrapper element

<div data-field="species" data-sortable="true">
    <strong>Species:</strong>
    <span>Human</span>
</div>
Warning: This will not work. Atlas will read the entire div as the value, including the "Species:" label. Filters will show "Species: Human" instead of just "Human".

Controls — Labels Go Outside Containers

data-sort, data-filters, and data-chips are containers that Atlas fills with generated content. Any content inside them will be overwritten.

✅ Correct: Labels outside the container

<div>
    <strong>Sort by:</strong>
    <div data-sort></div>
</div>

❌ Incorrect: Labels inside the container

<div data-sort>
    <strong>Sort by:</strong>
</div>
Warning: Content inside data-sort, data-filters, and data-chips will be removed when Atlas generates the controls. Always place labels outside these containers.

Key Points to Remember

  • data-field goes on the element containing the value, not on a wrapper
  • data-sort, data-filters, and data-chips are containers — Atlas replaces everything inside them
  • Labels must be placed outside these containers
  • You can style your member cards and controls however you want
  • Fields are filterable by default — use data-filterable="false" to opt out

For a complete reference of all available attributes, see the HTML API Reference.

For different ways to arrange your directory, see the Layout Examples.

Option A: Use CDN (Recommended)

The easiest way to install Atlas is to link to the CDN version. No files to upload — just copy and paste!

Add this to your Member List Header template:

<!-- CSS — CDN version -->
<link rel="stylesheet" href="https://atlas-directory.netlify.app/atlas.min.css">

<!-- HTML — your Atlas directory -->
<div data-atlas>
    <input data-search placeholder="Search members...">
    <div data-filters></div>
    <div data-sort></div>
    <div data-chips></div>
    <div data-results></div>
    <button data-layout="grid">Grid</button>
    <button data-layout="list">List</button>

    <div data-directory>
        <% MEMBERLIST_ROWS %>
    </div>
</div>

<!-- JavaScript — CDN version -->
<script type="module">
    import Atlas from 'https://atlas-directory.netlify.app/atlas.min.js';
    new Atlas();
</script>
Tip: No files to upload — just copy and paste these links!

Option B: Self-Host

If you prefer to host the files on your own server, upload the Atlas files to your JCink forum's file manager and link to them locally.

Add this to your Member List Header template:

<!-- CSS — link to the Atlas core styles -->
<link rel="stylesheet" href="YOUR ATLAS CSS FILE HERE">

<!-- HTML — your Atlas directory -->
<div data-atlas>
    <input data-search placeholder="Search members...">
    <div data-filters></div>
    <div data-sort></div>
    <div data-chips></div>
    <div data-results></div>
    <button data-layout="grid">Grid</button>
    <button data-layout="list">List</button>

    <div data-directory>
        <% MEMBERLIST_ROWS %>
    </div>
</div>

<!-- JavaScript — import and initialise Atlas -->
<script type="module">
    import Atlas from 'YOUR ATLAS JS FILE HERE';
    new Atlas();
</script>
Tip: The <% MEMBERLIST_ROWS %> tag is essential — it tells JCink where to insert each member row. Don't remove it!

Step 1: Edit Member List Templates

In your JCink ACP, navigate to: Manage Templates → Member List

Before you start: Back up your existing templates first! If you've already customised your Member List Header and Row templates, save a copy of the current code before replacing it.

You'll need to edit two templates:

  • Member List Header — The top of the member list
  • Member List Row — Each individual member row

Step 2: Member List Header

Replace the contents of your Member List Header template with this code. This sets up the Atlas container, controls, and directory wrapper. 

<!-- CSS — link to Atlas styles (use your own link if you are self-hosting) -->
<link rel="stylesheet" href="https://atlas-directory.netlify.app/atlas.min.css">

<div data-atlas>

    <!-- Search -->
    <input data-search placeholder="Search members...">

    <!-- Controls -->
    <div data-filters></div>
    <div data-sort></div>
    <div data-chips></div>
    <div data-results></div>

    <!-- Layout buttons (optional — default is grid) -->
    <button data-layout="grid">Grid</button>
    <button data-layout="list">List</button>

    <!-- Member directory wrapper -->
    <div data-directory>

        <!-- This is where Member List Row will be inserted -->
        <% MEMBERLIST_ROWS %>

    </div>

</div>

<!-- JavaScript — import and initialise Atlas (use your own link if you are self-hosting) -->
<script type="module">
    import Atlas from 'https://atlas-directory.netlify.app/atlas.min.js';
    new Atlas();
</script>

Step 3: Member List Row

Replace the contents of your Member List Row template with this code. This defines how each member card is displayed.

Full Example (with Labels)

<article data-member>

    <!-- Name — Searchable & Sortable -->
    <div>
        <strong>Name:</strong>
        <span data-field="name" data-searchable="true" data-sortable="true" data-filterable="false">
            <!-- |name| -->
        </span>
    </div>

    <!-- Face Claim — Searchable & Sortable, NOT Filterable -->
    <div>
        <strong>Face Claim:</strong>
        <span data-field="faceclaim" data-searchable="true" data-sortable="true" data-filterable="false">
            <!-- |field_#| -->
        </span>
    </div>

    <!-- Species — Filterable & Sortable -->
    <div>
        <strong>Species:</strong>
        <span data-field="species" data-sortable="true">
            <!-- |field_#| -->
        </span>
    </div>

    <!-- Occupation — Searchable, Filterable & Sortable -->
    <div>
        <strong>Occupation:</strong>
        <span data-field="occupation" data-searchable="true" data-sortable="true">
            <!-- |field_#| -->
        </span>
    </div>

    <!-- Faction — Filterable & Sortable -->
    <div>
        <strong>Affiliation:</strong>
        <span data-field="affiliation" data-sortable="true">
            <!-- |field_#| -->
        </span>
    </div>

    <!-- Homeworld — Filterable & Sortable -->
    <div>
        <strong>Hometown:</strong>
        <span data-field="hometown" data-searchable="true" data-sortable="true" data-filterable="false">
            <!-- |field_#| -->
        </span>
    </div>

    <!-- Status — Filterable & Sortable -->
    <div>
        <strong>Status:</strong>
        <span data-field="status" data-sortable="true">
            <!-- |field_#| -->
        </span>
    </div>

    <!-- Author — Filterable & Sortable -->
    <div>
        <strong>Author:</strong>
        <span data-field="author" data-sortable="true">
            <!-- |field_#| -->
        </span>
    </div>

</article>

Step 4: Map Your JCink Fields

Replace each <!-- |field_#| --> placeholder with your actual JCink field variables.

The field numbers (field_1, field_2, etc.) correspond to the custom fields you've set up in your JCink ACP. You may need to check your ACP to confirm which field number matches which semantic field.

Tip: You can use any semantic field names you like — Atlas doesn't care what you call them. Just make sure the data-field attribute matches what you use in your HTML.

Step 5: Add Custom CSS (Optional)

Atlas provides minimal core CSS. To make your directory look polished, you'll want to add custom styles.

Where to Add Your CSS

In JCink, you have two options:

  • Option A: Add to your forum's global CSS — Go to your JCink ACP → Skins & Templates → Style Sheets and add your custom styles into the right stylesheet for your skin. This applies the styles to your entire forum.
  • Option B: Add to the Member List Header — If you only want the styles to apply to your member list, you can add a <style> block directly in the Member List Header template.
Tip: If you're using Option A (global CSS) and want to completely replace the default Atlas styles, you can remove the atlas.min.css link from your Member List Header and copy the contents into your global CSS instead. You can find and copy the full CSS file here.

See the CSS Customisation Guide for styling guidance and ready-to-use CSS examples.

Step 6: Test Your Installation

After saving your templates, it's time to verify that Atlas is working correctly.

Quick Test

  1. Visit your member list page — For example, your forum's member list URL: https://yourforum.jcink.net/index.php?act=Members&max_results=1000
  2. Check for the search bar — You should see a search input field at the top
  3. Check for filters — You should see filter options for your fields (Species, Affiliation, Status, etc.)
  4. Check for sort buttons — You should see sort options (Name, Species, Occupation, etc.)
  5. Check member cards — Your members should appear in a grid or list layout
  6. Test functionality:
    • Try searching for a member name
    • Try clicking a filter option
    • Try clicking a sort button
    • Check that filter chips appear when filters are active

If Something Isn't Working

  • Open your browser's console (F12 → Console tab) and check for errors
  • Check that the CDN links are correct — the CSS and JavaScript should load
  • Check that <% MEMBERLIST_ROWS %> is in your Member List Header
  • Check that your Member List Row template has the correct field variables
  • Make sure you have at least one member with data in your custom fields
Tip: If you're having issues, check the Troubleshooting section below.

Troubleshooting

Members don't appear

  • Check that <% MEMBERLIST_ROWS %> is in your Member List Header
  • Check that the Member List Row template is correctly filled in
  • Check your browser console for errors

Filters don't appear

  • Ensure <div data-filters></div> is in your Member List Header

Search doesn't work

  • Ensure <input data-search> is in your Member List Header
  • Check that fields have data-searchable="true" (it's opt-in)

Sorting doesn't work

  • Ensure <div data-sort></div> is in your Member List Header
  • Check that fields have data-sortable="true" (it's opt-in)
  • Only fields present in ALL members will appear as sort options
