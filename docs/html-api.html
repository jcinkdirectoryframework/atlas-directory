HTML API Reference

All attributes and configuration options

Root Container

<div data-atlas>
    ...
</div>

data-atlas — Marks the root container. Every Atlas instance begins with this.

Loading State

Atlas automatically manages loading state to prevent flicker:

<!-- Atlas adds this during initialisation -->
<div data-atlas data-atlas-loading>
    ...
</div>

<!-- Atlas removes it when ready -->
<div data-atlas>
    ...
</div>

Atlas provides minimal CSS for this in src/styles/atlas.css.

Member Directory

<div data-directory>
    <article data-member>...</article>
    <article data-member>...</article>
</div>
  • data-directory — Container for all member cards
  • data-member — Individual member card

Member Fields

<article data-member>
    <span data-field="name">Din Djarin</span>
    <span data-field="species">Human</span>
    <span data-field="occupation">Bounty Hunter</span>
</article>

data-field — Defines a field value. The value is the semantic field name.

Field Attributes

AttributeDescriptionDefault
data-filterableWhether the field appears in filterstrue
data-searchableWhether the field is searchedfalse
data-sortableWhether the field appears in sort controlsfalse

Examples

<!-- Opt out of filtering -->
<span data-field="species" data-filterable="false">Human</span>

<!-- Opt in to search -->
<span data-field="name" data-searchable="true">Din Djarin</span>

<!-- Opt in to sorting -->
<span data-field="name" data-sortable="true">Din Djarin</span>

Controls

Controls can be placed anywhere within data-atlas. Atlas discovers them automatically.

Search

<input data-search placeholder="Search members...">

data-search — Marks a search input field.

Filter Container

<div data-filters></div>

data-filters — Container where Atlas generates filter interfaces.

Sort Container

<div data-sort></div>

data-sort — Container where Atlas generates sort buttons.

Filter Chips

<div data-chips></div>

data-chips — Container where Atlas displays active filter chips.

Result Counter

<div data-results></div>

data-results — Container where Atlas displays the result counter.

Layout Controls

<button data-layout="grid">Grid</button>
<button data-layout="list">List</button>

data-layout — Layout toggle button. Value must be grid or list. Default layout is grid. These buttons are optional. If omitted, Atlas uses grid layout only.

Tip: Layout preference persists to localStorage. If you only want grid layout, simply don't include these buttons.

Understanding data-field and Controls

This is the most important concept to understand when using Atlas: the data- attributes tell Atlas where to find data and controls, but they don't control how anything looks.

Design Freedom: You can style your member cards and controls however you want. Use any HTML structure, classes, or inline styles. The only requirement is that the data- attributes are on the correct elements.

data-field — The Value Must Be Contained

data-field must be placed on the element that contains the actual value. Labels, wrappers, and other display elements should not have data-field.

✅ Correct: data-field on the value element

<div>
    <strong>Species:</strong>
    <span data-field="species" data-sortable="true">Human</span>
</div>

Why this works: Atlas reads the value "Human" from the span. The label "Species:" is ignored — it's just for display.

❌ Incorrect: data-field on a wrapper element

<div data-field="species" data-sortable="true">
    <strong>Species:</strong>
    <span>Human</span>
</div>
Warning: This will not work. Atlas will read the entire div as the value, including the "Species:" label. Filters will show "Species: Human" instead of just "Human".

Controls — Labels Go Outside Containers

data-sort, data-filters, and data-chips are containers that Atlas fills with generated content. Any content inside them will be overwritten.

✅ Correct: Labels outside the container

<div>
    <strong>Sort by:</strong>
    <div data-sort></div>
</div>

<div>
    <strong>Filter by:</strong>
    <div data-filters></div>
</div>

<div>
    <strong>Active filters:</strong>
    <div data-chips></div>
</div>

❌ Incorrect: Labels inside the container

<!-- This will NOT work — Atlas will overwrite the label -->
<div data-sort>
    <strong>Sort by:</strong>
</div>
Warning: Content inside data-sort, data-filters, and data-chips will be removed when Atlas generates the controls. Always place labels outside these containers.

What About the Search Input?

data-search is different — it's a single element, not a container that Atlas fills. You can style it and wrap it with labels freely: 

<!-- This works — it's a single element -->
<div>
    <strong>Search:</strong>
    <input data-search placeholder="Search members...">
</div>

Quick Reference: Containers vs Single Elements

Attribute Type What Happens Can You Put Content Inside?
data-search Single Element Atlas binds to it — doesn't replace content ✅ Yes (it's an input, it has no children)
data-layout Single Element Atlas binds to it — doesn't replace content ✅ Yes (it's a button, it has no children)
data-sort Container Atlas replaces all content with buttons ❌ No — content will be removed
data-filters Container Atlas replaces all content with filters ❌ No — content will be removed
data-chips Container Atlas replaces all content with chips ❌ No — content will be removed
data-results Container Atlas replaces all content with the counter ❌ No — content will be removed
data-directory Container Atlas discovers members inside it ✅ Yes — this is where your members go
data-member Element Atlas discovers data-field inside it ✅ Yes — this is your member card
Key takeaway: The data- attributes tell Atlas where to find data and controls. Everything else — layout, colours, spacing, fonts, labels — is yours to design.

Performance

Atlas automatically optimises performance for large directories. No configuration is required — it just works.

Lazy Rendering

When a directory has more than 300 members, Atlas automatically switches to lazy rendering. Only members visible in the viewport (plus a buffer) are rendered in the DOM. As you scroll, new members are loaded in batches of 25.

This keeps the DOM small and responsive, even with 1,000+ members.

Filter Caching

Filter results are automatically cached. Applying the same filter multiple times is instant — no recomputation needed.
